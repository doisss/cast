# Изменения

Версии — по [semver](https://semver.org/lang/ru/): `X.Y.Z`, где Y растёт при новых
возможностях, Z — при исправлениях. Поставить любую версию:
`bash install.sh --version vX.Y.Z` (см. README, раздел «Версии»).

## v0.3.0 — в работе (ветка web)

- Веб-интерфейс: `cast web` открывает cast в браузере. Ввод цели как в
  `cast scan`, ход проверки с полосой загрузки, результат с фильтрами и
  поиском, строки PASS у Docker Bench, скачивание HTML и JSON.
- `cast web` сразу доступен и с этой машины, и с других машин сети: адреса
  для входа печатаются при запуске (например, чтобы зайти с хоста на ВМ);
  `cast web --local` — только с этой машины. Если порт 8765 занят, берётся
  следующий свободный; если включён ufw — подсказка, какой порт открыть.
- Вход в веб по логину и паролю. При первом `cast web` они спрашиваются в
  терминале (Enter вместо пароля — cast придумает случайный) и сохраняются в
  `~/.config/cast/web.json` с правами 600; пароль хранится хэшем scrypt, не
  открытым текстом. Сменить: `cast web --reset-password`. После 5 неверных
  попыток с одного адреса вход с него закрыт на минуту. Кнопка «Выйти».
- Главная страница веба. Слева — проводник: колонки «Имя», «Дата изменения»,
  «Размер», «Тип» (сортировка по щелчку), стрелки «назад» и «вперёд», путь
  сегментами (щелчок по пустому месту — вписать путь целиком), «Фильтр» и меню
  «Действия» (Открыть, Открыть с помощью…, Копировать путь, Переименовать,
  Удалить, Обновить, Новая папка, Показать скрытые файлы, Выбрать всё,
  Закрыть). Правая кнопка по файлу: Сканировать, Открыть, Открыть с помощью…
  (просмотр в браузере, скачать), Копировать путь, Переименовать, Удалить,
  Обновить, Новая папка; по папке — без первых трёх. Выбор нескольких —
  Ctrl и Shift, они проверяются по очереди. В центре «Что проверить?» — всё,
  что cast нашёл на машине, по модулям: эта машина (Docker-хост, вся ФС «/»),
  запущенные контейнеры, образы Docker, кластер Kubernetes, Dockerfile,
  манифесты Kubernetes, Helm-чарты, Terraform, CloudFormation, docker-compose,
  папки проектов, git-репозитории, архивы образов, SBOM, образы дисков ВМ,
  распакованные ОС; щелчок — и проверка началась. Файлы ищутся в домашней
  папке и папке запуска (служебные папки пропускаются, обход ограничен по
  времени). Ввод цели вручную остался под «Вписать цель вручную». Справа —
  проверки этого запуска и движки.
- Результат: пакеты, установленная версия и «Исправлено в» — отдельными
  колонками, одна CVE в пакетах-близнецах — одной строкой; ошибки конфигурации
  — по месту в файле, как в терминале: код с отметками `[` / `┌ │ └` и кусок
  YAML (серым — менять не нужно, зелёным — добавить или изменить, без подписей);
  переключатель «Код из файла» — в строке фильтров; убраны колонка «Приор.» и
  строки «базовая критичность». Текст переносится по ширине окна, прокрутки
  вбок нет; в узком окне строка таблицы становится карточкой.
- Кластер Kubernetes: ошибки конфигурации — по ресурсам, внутри — по местам,
  как у файла (код, кусок YAML); уязвимости — по ресурсам, внутри — по образу
  или программе в образе (`usr/local/bin/kube-proxy`).
- `cast web` сам перезапускается через sudo (host и контейнеры проверяются
  только от root); `--no-sudo` — от текущего пользователя. Под sudo тот же
  пароль, тот же kubeconfig и движки из PATH пользователя, браузер
  открывается от пользователя, новые папки принадлежат ему; удалять корень и
  системные папки из веба нельзя. Кнопка «Новая проверка» — и у невыполненных
  проверок.

## v0.2.1 — в работе (ветка dev)

Вывод в терминале (замечания после прогона demo.sh):

- таблица уязвимостей больше не обрезается в узком окне: ширины колонок считаются
  от окна, в окне уже ~110 символов «Где» переходит строкой под название;
- в таблице уязвимостей нет колонок «Приоритет» и «Источник» (в JSON и HTML
  остались); одна CVE в пакетах из одного исходника с теми же версиями
  (musl и musl-utils) — одна строка со списком пакетов, счётчики как у Trivy;
- Dockerfile показывается как конфигурации: по строкам файла, с кодом, правила
  про файл целиком — группой «весь файл»; одна строка-причина отмечена `[`, как
  у Trivy; добавлено сообщение Trivy (Message) о том, что именно не так в файле
  (в JSON — поле `message`);
- у ошибок конфигурации убрана подпись «в файле:» перед куском YAML; кусок YAML
  строится и для пути без кавычек (`Add 'ALL' to containers[]...capabilities.drop`),
  значения списков (`drop`, `add`) — пунктом `- ALL`;
- кусок YAML привязан к файлу: контейнер строкой `- name: web` (имя из сообщения
  Trivy); по строкам кода от Trivy: что менять не нужно — серым, что добавить
  или изменить — зелёным, без подписей; значение, которое Trivy не назвал, —
  `<ваше значение>`;
- места в файле конфигурации сортируются только по серьёзности, а при равной
  серьёзности первым идёт правило про файл целиком (DS-0002, нет USER);
- Docker Bench: PASS — серыми строками таблицы внизу раздела, а не номерами
  в одну строку (с `--top` — по-прежнему номерами);
- `cast engines` пишет о других копиях движка («также установлен: /usr/bin/trivy»);
- «эта машина» → «текущая машина».

Проверки и демо:

- папка `realtests/`: `setup.sh` готовит машину целиком, на чистом Debian ставит
  недостающее (curl, cast с движками, Docker), скачивает образы и базу Trivy и
  поднимает кластер kind (`--no-cluster` — без него), `run.sh` запускает
  `demo.sh all` и проверяет, что ни одна команда не
  вернула код 2, `teardown.sh` всё убирает;
- demo.sh: выровнена итоговая таблица, в журнал не пишутся кадры индикатора,
  `DEMO_RESULTS` — файл с итогом для `realtests/run.sh`.

## v0.2.0 — 01.11.2026

Новые виды целей (cast сам определяет, что ему дали):

- конфигурации: Kubernetes-манифесты, Terraform, Helm (папка или `Chart.yaml`),
  CloudFormation, docker-compose — `trivy config`;
- архив образа (`docker save`, OCI-архив) — `trivy image --input`;
- корневая ФС (папка с `etc/os-release`, в том числе `/`) — `trivy rootfs`;
- git-репозиторий по ссылке — `trivy repository`;
- SBOM (CycloneDX, SPDX) — `trivy sbom`;
- образ диска ВМ (`.img`, `.qcow2`, `.vmdk`, …) — `trivy vm`;
- кластер Kubernetes (`cast scan cluster`) — `trivy kubernetes`;
- явные формы: `cast scan config|rootfs|archive|sbom|vm|repo|container ...`.

Вывод:

- ошибки конфигурации собраны по месту в файле: код показан один раз, под ним
  таблица находок и кусок YAML «в файле:» с тем, что исправить;
- Docker Bench: проверки по разделам CIS 1–7, PASS одной строкой, объекты
  пунктами, пометки «(ручная)» и «(устаревшая)», пояснение к Score; в скане
  контейнера сказано, какие проверки запущены (4.1 и раздел 5);
- одна уязвимость в разных файлах больше не склеивается в одну строку (на «/»
  было 136 строк из 484 записей Trivy, стало столько же, сколько у Trivy);
- ошибки ввода по-русски, сокращения флагов выключены (`--to 3` больше не
  становится `--top 3`);
- «Сканирование образа НЕ выполнено» (была опечатка «выполнена»).

Прочее:

- `demo/demo.sh` — показ всех возможностей одной командой;
- `install.sh --version vX.Y.Z` и `--list-versions`;
- автотестов: 107 → 197.
